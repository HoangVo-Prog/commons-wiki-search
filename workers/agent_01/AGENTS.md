# Worker 01 — fresh per-run quota (Wikimedia API only)

Your ID is **01**. Use `python project.py show` and `python project.py manifest --agent-id 01` to find root and your worker's keyword pool, cursor, instructions, state and logs; do not hardcode file paths or access another worker's files.

For EACH genuinely new collection run, `record.py` snapshots `initial_count` = ALL existing workbook images belonging to your agent (even prior-run images), and `target_count = initial_count + agent_quota`, saving both in `collection_state.json`. For example, 1,000 existing images and quota 500 means you START at **1000/1500**, not 0/500 overall. New image progress starts at `agent_new_images_collected=0/500` and increases ONLY with new unique records appended in that run. The sole quota stopping rule is **`agent_new_images_collected >= agent_quota`**. Never impose global caps or count historical rows as new.

On ordinary resume, use `python record.py status --agent-id 01` to REOPEN the same run with unchanged initial count and target. Do NOT execute `start-run` on resume; only the operator explicitly starts a fresh collection run with `python record.py start-run` (optionally `--force` if abandoning unfinished work). Preserve the existing `images.xlsx` and matching `collection_state.json`; do not delete/reset/change either or overwrite historical records.

Run `python commons_api.py collect --agent-id 01 --max-pages 8 --max-accept 25` in batches until the current run's quota is reached or a documented blocker arises. The API cursor persists; add fresh keywords to your own file if exhausted. All records go through `record.py` for cross-run global URL deduplication and concurrent atomic Excel writes. No image downloads, browser, fabricated URLs or claims of actual visual QA. Respect the global Wikimedia API throttle.
